# Restore calsync and add privacy/scheduling controls

## Summary

Got calsync running again after a long dormancy (stale run.sh path, no `node_modules`/`config.ts`/`credentials.json`, expired Google OAuth tokens), then extended it with per-source privacy modes, a shorter default sync window, and free/busy + color overrides. Ended the session by migrating the live target from the main `carbonfact.com` work calendar to a dedicated mirror calendar and cleaning up the events created during testing.

## Decisions

- **Fixed a real regression in `app.ts`**, not just environment setup: the last commit before this session ("linting fixes") had turned the recurring-CalDAV-event loop's `while ((nextOccurrence = it.next()))` into a `continue`-based loop that never re-called `it.next()` on the skip path (infinite loop risk) and replaced a `.forEach`-style `return` with a bare `return` inside a `for...of`, aborting the whole sync after the first recurring event. Restored the original iteration and changed the trailing `return` to `continue`.
- **Diagnosed the OAuth 7-day-refresh-token-expiry** as the root cause of the original "why did this stop working" complaint: the GCP OAuth consent screen was stuck in "Testing" status, which Google hard-caps at 7-day refresh tokens regardless of scope. Publishing to Production fixed it — no Google review was actually required, the "Publish app" button was just blocked by incomplete Branding config (an app logo present that forces verification, plus empty home page/privacy policy links, plus two stale/unrelated authorised domains — `supabase.co` and `calsync.com` — left over from whenever the GCP project was first created).
- **Added `visibility: 'private'` as a per-source alternative to `redactedSummary`**: instead of replacing the summary with a generic label, keep summary/description untouched and mark the copied event's Google Calendar visibility as `'private'`, so only the target calendar owner sees details. Mutually exclusive with `redactedSummary`; `visibility` wins if both are set.
- **Fixed a real privacy bug while implementing the above**: in redact mode, `sync.ts` was *appending* calsync's bookkeeping text to the original description instead of replacing it, so the full original description always leaked through even when the summary was redacted. Now fully dropped and replaced. This fix also resolved 8 pre-existing failing tests in `sync.test.ts` that had been silently red before this session.
- **Changed `daysToSync` default from 365 to 14**: since calsync deletes/recreates target events within its fetch window on every run, a shorter window limits the blast radius of a bad sync while still giving enough visibility if run frequently.
- **Added `showAs: 'free' | 'busy'` and `colorId` per-source overrides**: `showAs` forces the copied event's transparency regardless of the source's own free/busy status; `colorId` sets a fixed Google Calendar color (used Graphite/`8` for a "grey" request).
- **Moved the sync target from the main `romain@carbonfact.com` work calendar to a dedicated secondary calendar** the user created specifically for this, to keep mirrored events out of the primary calendar. Reused the existing `romain@carbonfact.com` OAuth token under the new calendar's ID as the tokens.json key, since Google Calendar API auth is scoped to the account, not the individual calendar — avoided a redundant OAuth consent round-trip.

## Learnings

- Google Workspace domains can enforce a separate "API Controls / App Access Control" admin policy on top of the standard OAuth consent screen. This only bit `romain@carbonfact.com` (a Workspace account) after the app moved from Testing to Production status — the personal Gmail account was unaffected, just showing the standard "unverified app" click-through warning. Needed the Workspace admin to explicitly allowlist the app's two scopes (`calendar.readonly`, `calendar.events`) before Calendar API calls stopped failing with `access_not_configured`.
- Cleaning up mis-targeted synced events is safe and precise because every calsync-managed event carries a fixed fingerprint string in its description — filtering ~3,900 real calendar events down to exactly the 11 calsync-created ones for deletion had zero ambiguity.
